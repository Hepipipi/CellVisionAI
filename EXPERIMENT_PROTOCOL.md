# Протокол проверки CellVision (шаблон, эксперимент ещё не проведён)

## Цель

Оценить повторяемость сегментации отдельных объектов эритроцитов и исследовательскую классификацию морфологических форм на независимых микрофотографиях. Этот протокол не оценивает клиническую диагностику и не подтверждает пригодность для пациентов.

## Данные и происхождение

Заполнять до начала анализа: название набора, ссылка и версия; лицензия и разрешённое использование; число пациентов, мазков, полей зрения и исходных кадров; окраска; увеличение и пиксельный масштаб; микроскоп/камера; критерии включения и исключения. Не записывать персональные данные пациентов.

Для начального исследования можно рассмотреть [Expert Annotated RBC (Figshare)](https://figshare.com/articles/figure/Expert_Annotated_RBC/13053968) и [PathOlOgics_RBC (Figshare)](https://figshare.com/articles/dataset/PathOlOgics_RBCs_Cells_zip/24119511). Перед использованием проверьте лицензию, состав аннотаций, согласие на предполагаемое использование и формат данных. Для малярии существует набор [NLM malaria microscopy](https://data.lhncbc.nlm.nih.gov/public/Malaria/index.html); он требует отдельного протокола, а интерпретация мазка должна оставаться у опытного микроскописта.

**Фактическое состояние:** в проекте есть RedTell DSE (Zenodo, CC BY 4.0) для обучения/оценки морфологического классификатора. Отдельно выполнено предварительное сравнение Watershed-маски с эталонными масками RedTell на 30 отложенных кадрах; цифры и примеры см. ниже и в `data/reports/redtell_segmentation_evaluation.json`. AneRBC, BCCD и другие внешние наборы не подключены как тестовые данные CellVision. Ни размер, ни лицензия датасета не заменяют независимую проверку конкретной версии данных. Метрики из чужих статей нельзя приписывать CellVision.

## Завершённая предварительная проверка

Скрипт `evaluate_redtell_segmentation.py` сравнивает текущую бинарную маску CellVision с инстанс-маской набора RedTell DSE на 30 кадрах, чьи ID кратны пяти. Это те же исходные кадры, которые удерживались для существующей проверки морфологического классификатора. Результат: средний пиксельный Dice 0,115, IoU 0,062, pixel precision 0,383, pixel recall 0,070; средний абсолютный недосчёт — 22,1 клетки на кадр (средний signed bias −19,8). На этих кадрах эталон содержит 1 261 клетку, алгоритм выделил 667 объектов.

Результат слабый: контуры и подсчёт ненадёжны для этих фазово-контрастных кадров. Эти числа не являются клиническими метриками, не говорят о вероятности анемии и не доказывают, что алгоритм так же работает на всех окрашенных мазках. Идентификаторы пациентов для RedTell DSE отсутствуют, поэтому holdout по исходному кадру не означает пациент-независимую проверку. Контактный лист `web/assets/redtell_segmentation_examples.jpg` содержит реальные кадры, маски и визуализацию ошибок с атрибуцией CC BY 4.0.

Независимые разметки двух людей по-прежнему не собраны. Межэкспертное согласие нельзя сообщать, пока два наблюдателя действительно не размечают одни и те же объекты независимо; интерфейс сравнения для этого подготовлен.

## Разметка и разделение

1. Сначала разделить данные по пациенту (и исходному мазку), после чего формировать клетки. Все поля и кадры одного пациента должны оставаться в одном разбиении.
2. Два специалиста независимо размечают контуры эритроцитов, а затем классы: нормальная форма, микроцит, макроцит, сфероцит, мишеневидная клетка, шистоцит/фрагмент, серповидная форма, овалоцит, прочая форма, артефакт/не-клетка.
3. Специалистам предоставить инструкцию с изображениями-примерами; измерить межэкспертное согласие и разрешить разногласия третьей оценкой или консенсусом.
4. Сформировать обучающую, валидационную и один раз используемую независимую тестовую группы. Сохранить таблицу соответствия псевдонимизированных исходных снимков и разбиений.
5. Импорт в текущем MVP использует ZIP `train/<класс>/<crop>.png` и `test/<класс>/<crop>.png`. Это обучает классификатор отдельных клеток. В UI можно нарисовать полигоны эталонной маски на одном кадре и получить Dice/IoU; пакетный импорт экспертных масок всего публичного датасета и object F1 пока не реализованы.

## Процедура

Зафиксировать версию кода, модель, параметры сегментации, обработку неудачных файлов и все исключения. Для каждого исходного кадра сохранить оригинал, выходную маску/контуры, экспертные метки и причины ошибок. Повторить анализ на серии кадров без ручной подстройки параметров под тестовые данные. Отдельно сгруппировать результаты по устройству, окраске, качеству фокуса и плотности клеток.

## Метрики

- **Сегментация объектов:** precision, recall и F1 при заранее выбранном правиле сопоставления (например, IoU ≥ 0.5), доля пропущенных и лишних объектов.
- **Сегментация маски:** Dice и IoU относительно экспертной маски; усреднение сначала внутри пациента, затем по пациентам.
- **Классификация:** матрица ошибок; precision, recall, F1 для каждого класса; macro-F1; сбалансированная accuracy; поддержка (число объектов) каждого класса.
- Доверительные интервалы получать бутстрэпом по пациентам, не по клеткам. Отдельно перечислить ошибки на размытых снимках, наложениях, загрязнении, редких формах и нерепрезентативной окраске.
- Качество кадра в интерфейсе сейчас оценивается эвристиками резкости, яркости и клиппинга; это не валидированная шкала качества.
